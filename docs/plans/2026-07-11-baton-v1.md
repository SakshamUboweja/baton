# baton — cross-harness workflow failover (v1 plan)

Working name: **baton** (rename is trivial; final name is Saksham's call before repo creation).

## Context

Saksham's AI-coding workflow spans three harnesses — Claude Code, OpenAI Codex CLI, and Cursor — and breaks whenever one platform's usage limits run out mid-task. Work state, plan context, and the writer/reviewer role assignments are trapped in the dying session. His handwritten notes describe a three-layer system (ideal-loop creator with smoke-test gate; dual-worktree adversarial write/review pipeline; cross-platform workflow portability). **Milestone 1 (this plan): the cross-platform failover layer** — chosen by Saksham as the foundation, since it addresses the stated pain point and the other layers run on top of it.

Research confirmed the white space: Databricks' Omnigent (June 2026) is the closest analog but replaces native configs with its own YAML and ships **no usage-limit failover**; nothing else does harness-level failover either (closest is model-level switching). The portability standards to build on already exist: AGENTS.md (Linux Foundation/AAIF-governed; native in Codex + Cursor; bridged into Claude Code via an `@AGENTS.md` import in CLAUDE.md) and the Agent Skills standard (SKILL.md; native in Claude Code + Codex).

## Locked decisions (from Saksham, this session)

1. **First milestone**: cross-platform failover layer. Loop-creator and dual-worktree pipelines are later milestones; leave seams.
2. **Capture**: continuous checkpointing via harness hooks **plus** an explicit `/handoff` finalize command that records reason-for-switching.
3. **Platforms**: all three from v1. Claude Code gets the deep integration (plugin with hooks); Codex and Cursor get lighter native adapters.
4. **Receive flow**: intake (original platform + reason) → load bundle → role-matrix remap → auto-continue the task.
5. **Bundle home**: gitignored `.handoff/` directory inside the repo.
6. **Architecture**: one repo — harness-agnostic core Node CLI + three native adapters + templates + tests.
7. **Attribution (hard invariant)**: ZERO AI mentions in git history — no `Co-Authored-By`, no "Generated with Claude Code" — permanently. During initial construction (pre-v1), all commits are authored solely by `SakshamUboweja <ssakshamu@gmail.com>` with frequent, regular commits to main (contributions accrue to his GitHub profile); external human OSS contributors are welcome post-v1. Enforced via `{"attribution": {"commit": "", "pr": ""}}` in Claude Code settings (the old `includeCoAuthoredBy` boolean is deprecated) + a doctor check.
8. **AGENTS.md / CLAUDE.md**: the tool scaffolds an ideal pair into any project (this repo dogfoods them). Design grounded in the official Fable 5 and GPT 5.6 prompting guides (fetched; distilled below). Strongest models get latitude on the design.
9. **Development methodology** (governs building this repo AND is encoded in the templates as the product's workflow):
   - Fable 5 writes the plan doc → **GPT 5.6 Sol xhigh reviews it (Gate 1)**.
   - Decompose into tasks/subtasks.
   - Per subtask: **Opus 4.8 writes unit tests first, GPT 5.5 xhigh verifies the tests**; the two keep each other in line during implementation.
   - At the end: **GPT 5.6 Sol xhigh and Fable 5 xhigh run independent reviews**; feedback is collated and implemented.
   - Overall: a goal with genuine constraints, looped until the constraints are met. Review artifacts under `reviews/<task-id>/` with verdicts `{APPROVED, APPROVED_WITH_NOTES, BLOCKED}` (pattern from Saksham's wt-* repos).

## Research findings that shape the design (verified 2026-07-11)

- **Codex plugin (installed, v1.0.4) is the implementation pattern**: single Node entrypoint invoked as `node "${CLAUDE_PLUGIN_ROOT}/scripts/<x>.mjs" <subcmd>`; hooks in `hooks/hooks.json` (SessionStart/SessionEnd/Stop) read event JSON on stdin and can emit `{"decision":"block","reason":…}`; commands/agents/skills as markdown with frontmatter; per-workspace state dir; structured-output JSON schemas for reviews. It has **no usage-limit handling** — our failover logic is net-new.
- **Superpowers plugin (installed) is the cross-harness packaging pattern**: one repo ships `hooks/hooks.json` (Claude) + `hooks-cursor.json` (Cursor, camelCase events), a polyglot `run-hook.cmd`, and `.codex-plugin` / `.cursor-plugin` / `AGENTS.md` descriptors. Hook output differs per harness (Claude: `hookSpecificOutput.additionalContext`; Cursor: `additional_context`) — branch on `$CURSOR_PLUGIN_ROOT`.
- **Limit-detection signals** (Gate-1 verified, 2026-07-11): structured signals FIRST, text signatures as fallback tier.
  - Claude Code: **`StopFailure` hook event** fires when a turn ends on an API error, with matcher filtering by error type (`rate_limit`, `overloaded`, `billing_error`, `server_error`, …) — the primary, structured limit-death signal. Output/exit code ignored (observability-only), so a checkpoint there is safe by construction. Text fallback: the stable strings `You've hit your session limit · resets …` / `weekly limit` / `Opus limit`.
  - Codex (>= 0.144): **lifecycle hooks exist** (`SessionStart`, `PreToolUse`, `PostToolUse`, `PreCompact`, `PostCompact`, `UserPromptSubmit`, `SubagentStop`, `Stop`; configured via `~/.codex/hooks.json`, `<repo>/.codex/hooks.json`, or config.toml `[hooks]`; stdin JSON with `session_id`, `cwd`, `model`, `transcript_path`). No StopFailure equivalent → limit death bounded by last Stop checkpoint. Text fallback: `You've hit your usage limit…`; `codex exec --json` exits non-zero.
  - Cursor: weakest — BYO-key returns `{"error":"Too Many Requests", …}`; managed-billing schema undocumented. Heuristics + timeouts, `confidence: low`.
- **Session handoff prior art**: HANDOFF.md markdown is the accepted lossy-universal mechanism; schema-level session transplants (authsec-bridge) are brittle — v1 stays markdown+JSON, no session-file surgery.
- **Local surfaces available on this machine**: `codex` CLI (gpt-5.6-sol, xhigh) with empty-but-supported `~/.codex/prompts/`; `cursor-agent` CLI (reads AGENTS.md + CLAUDE.md natively); `.agents/skills` is the official Codex skills path; Cursor project hooks via `.cursor/hooks.json` (onPreEdit/onPostEdit/onPreCommit/onApprove).
- **Running the methodology's models from Claude Code**: Agent tool model overrides (opus/fable) + codex companion (`… codex-companion.mjs task --model gpt-5.6-sol|gpt-5.5 --effort xhigh`, read-only sandbox, structured output).

## Prompting-guide distillation (for the AGENTS.md/CLAUDE.md templates)

- **Fable 5** (platform.claude.com guide): strong instruction-following — brief steering beats enumeration; state boundaries (pause only for destructive/irreversible/scope-change/user-only input); "when you have enough information to act, act"; audit progress claims against tool evidence; parallel subagents with async communication; provide a memory/notes location; fresh-context verifier subagents beat self-critique; over-prescriptive skills degrade output; never instruct reasoning echo (triggers refusals).
- **GPT 5.6** (developers.openai.com guide): hierarchy Role → Goal → Success criteria → Constraints → Tools → Stop rules; outcome definition over process prescription; trimming repeated rules improved evals 10–15% and cut tokens 41–66%; ALWAYS/NEVER only for true invariants; state each policy once; name the current phase for long work; explicit validation guidance; avoid contradictions, universal defaults, blanket brevity, personality words.
- **Template consequence**: shared invariants live exactly once in AGENTS.md (lean, hierarchical); CLAUDE.md is an `@AGENTS.md` import plus a short Claude-specific block (memory location, subagent guidance); any Codex-specific steering gets its own clearly-scoped short section.

## Design

_(Sections below synthesized from two Plan-agent designs — core engine; adapters/templates/methodology — merged after Gate-1 review.)_

### Core engine (`core/`)

**Language/tooling**: plain ESM JavaScript (`.mjs`) + JSDoc types checked by `tsc --noEmit --checkJs` (dev-only dep). No build step — hooks invoke source directly (`node "${CLAUDE_PLUGIN_ROOT}/…"`), same as the proven codex plugin. **Zero runtime dependencies**; arg parsing via `node:util` `parseArgs`; **`node:test`** as the framework (golden-file helper ~40 lines with `UPDATE_GOLDEN=1`). Node >= 20. Every command's `run()` takes an injected `io` object (`{cwd, env, stdin, stdout, stderr, fs, execFile, now}`); pure logic (reducers/renderers/resolvers/classifiers) is data-in/data-out; tests run over an in-memory fs fake plus a thin real-fs integration layer.

**CLI surface** (`baton <cmd> --json`): `checkpoint`, `finalize`, `detect`, `remap`, `receive`, `init`, `doctor`, `status`, `purge-transcript`, `recover` (forced lock recovery). Frozen exit-code contract: `0` ok · `1` command failure · `2` usage error · `10` usage-limit · `11` throttle · `12` auth · `13` other-error. `--json` mode prints exactly one envelope `{ok, data, warnings, error}` on stdout. `baton wrap -- <cmd>` (PTY supervisor) is **deferred post-v1** — hook-driven detection suffices; the name/contract is reserved.

**Bundle** (`.handoff/`): single active bundle = `bundle.json` (atomic tmp+rename snapshot, `.bak` of previous good) + `journal.ndjson` (append-only events, torn-tail tolerant) + rendered `HANDOFF.md` + `history/` (unified retention: last 10 entries **per type** — finalize freezes, takeover archives, receive archives — each = frozen snapshot plus rotated journal; receipts needed for replay/audit are always preserved within retained entries). Load = snapshot + replay journal entries past `journalSeq`; recovery paths: `.bak` + replay, or full journal rebuild. Schema `baton/bundle@1`: origin platform/model, task goal/constraints/acceptance, plan steps with status, capped decisions log, files touched, role assignments, git branch/HEAD/dirty summary, handoff finalize block (`status: open|sealed|received` + `receive_log[]`), compaction markers. Size discipline is **deterministic truncation only** (decisions capped first-20+last-150 with marker; no LLM summarization).

**Concurrency** (Gate-1 additions, iterations 1+2): all bundle mutations run under a repo-scoped lock — `.handoff/lock` acquired via atomic `mkdir`/`O_EXCL`, containing `{writerId: <platform>-<pid>-<sessionHint>, fencingToken: <random per acquisition>, acquiredAt, heartbeatAt}`. **Lock model (iterations 3+4)**: mutation locks are **operation-scoped** — acquired for the duration of one command's mutation and released, never held across turns; logical session ownership lives in `bundle.json` (the active `origin`/generation), not in the lock. Lock metadata (host, pid, process start time, fencing token) is written atomically with acquisition; a crash between lock creation and metadata publication reads as torn metadata. Recovery rules, conservative on every OS: automatic recovery only when the owner is **provably dead** (same host, pid gone or pid/start-time mismatch); a same-host owner confirmed alive is **refused** — including `recover --force` — with the instruction to terminate that process first; missing/torn/cross-host/unverifiable owner metadata is treated as **unsupported for automatic recovery** (refusal with explanation), never as safe-to-steal. Fencing tokens remain a fast-abort layer. Tests: force attempted against a live paused writer (refused), crash between lock creation and metadata publication, owner paused after its final token check, torn-metadata refusal. Journal entries carry `writerId`; sequence numbers are allocated under the lock. **Semantic isolation**: v1 enforces one active task — a checkpoint whose `sessionHint`/origin doesn't match the active bundle is rejected with an actionable warning (`--take-over` supersedes: archives the current bundle to `history/` and starts fresh), so two unrelated sessions can't merge goals/files/decisions into one handoff. `receive` is a core-owned two-phase transaction. `receive --prepare` validates + resolves roles + returns a one-time receipt token and the resume prompt without mutating state; the token **binds** the bundle revision (journalSeq), normalized intake, config digest, target platform+session, the probe snapshot used for remap, **and a content-sensitive prepare-time git digest** — HEAD + branch + hashes of the staged and unstaged diffs + a bounded untracked-files digest (path + size + content hash, capped) — so a file that stays `M` but changes content still invalidates the token. `--commit` re-derives and compares every bound input, rejecting any drift (intervening checkpoint, config edit, HEAD move, content change, probe change) and requiring re-prepare; each declared drift input has its own rejection test. `receive --commit <token>` performs one atomic transition: `sealed → received` (normal) or `open → received` (the primary failure case: limit death before finalize; commit writes a receive-generated degraded seal recording intake origin/reason, flagged `degraded-seal`) — and in the same transition **adopts the receiving platform/session as the bundle's active owner and opens a fresh writable generation** (`generation` counter incremented, `status: open`), archiving the prior seal + receipt to `history/`. The receiving session's subsequent checkpoints are therefore first-party, and the bundle is immediately receivable again if the new platform also dies — chained A→B→C failover is contract-tested with checkpoints fired immediately after each receive. Cancellation or a competing receiver leaves state untouched; double-commit fails cleanly. Identical semantics on every adapter; six-direction contract tests cover sealed + unsealed variants. Tests: concurrent writers, provably-dead takeover, fencing-token abort incl. pause-after-final-check, foreign-session rejection/take-over, prepare-vs-checkpoint races, prepare-without-commit, double-commit, competing receivers, chained failovers.

**Journal rotation & crash recovery** (Gate-1 additions, iterations 1–3): on every finalize, crash-safe order = write a rotation marker → write frozen snapshot to `history/` → rename `journal.ndjson` alongside it → start a fresh journal seeded with the snapshot's `journalSeq` → clear marker. On load, a present marker deterministically rolls the rotation forward (if the snapshot landed) or back (if not); the same marker pattern governs interrupted forced takeovers and interrupted purges (purge resumes from its marker until the whole tree is clean). Retention: last 10 rotations pruned with the history. Doctor warns at journal > 5 MB; perf test: 10k-event replay < 1 s. **Filesystem support boundary: v1 supports local filesystems only** — lock and rename atomicity are not guaranteed on network/shared mounts (NFS/SMB/cloud-sync folders); doctor detects and warns, README states it.

**Root discovery & degraded modes** (Gate-1 additions, iterations 1+2): repo root = nearest ancestor containing `.handoff/` or `baton.config.json`, else `git rev-parse --show-toplevel` (worktree-aware: linked worktrees resolve to their own toplevel, shared state stays per-worktree), else cwd — `--root <path>` overrides; nested/monorepo launches therefore resolve to the same bundle deterministically, but **discovery never crosses the boundary of a nested independent git repository** (a `.git` between cwd and a candidate root stops the walk) unless `--root` says otherwise. Non-git directories: supported — `git` section is null, git-dependent features degrade with explicit warnings. Read-only sandboxes (EACCES/EROFS on `.handoff/`): checkpoint fails open with a warning naming the user-executed fallback (`baton checkpoint` run manually outside the sandbox; `receive --print-prompt` never needs writes until `--commit`). All git invocations carry a 5 s timeout (configurable); timeout → git section marked `unavailable`, never a hang.

**Transcript policy** (Gate-1 additions, iterations 1+2): transcript-tail capture at PreCompact is **opt-in and off by default** (`capture.transcriptTail` in `baton.config.json`), bounded (last 10 messages, 8 KB cap), passed through a secret-redaction filter (common credential/token patterns; fixtures with planted secrets prove redaction), stored in a dedicated bundle field excluded from HANDOFF.md by default. `baton purge-transcript` removes the field from **every retained copy** — active snapshot, `.bak`, journal (rewrite-and-rotate under lock), and all `history/` freezes — with a test asserting planted secrets are absent from the entire `.handoff/` tree afterward. **Diagnostics logging contract (iteration 4)**: `.handoff/log/` entries are metadata-only and redacted — raw hook payloads never enter them (fixture-proven) — with bounded retention (last 50 entries / 7 days) and inclusion in the whole-tree purge test.

**Checkpoint engine**: adapters send pre-normalized `baton/event@1` on stdin (the real API); raw hook payloads get best-effort per-platform extraction (`normalize.mjs`) that never throws — unknowns degrade to `note` events. Idempotent via dedupe keys; journal append always, snapshot rewrite throttled (≥10 events / 30 s / important event types). **Hook-safety rule: exit 0 on all soft failures** so a checkpoint can never break the host harness (`--strict` for CI). `finalize --reason "…" [--reason-class] [--to]` records the switch reason (class inferred from text via the classifier when omitted), refreshes git state, freezes history.

**Limit detector**: two tiers — **structured signals first** (Claude Code `StopFailure` matcher error types; documented limit-specific fields in codex JSON output), text signatures as fallback. **Exit-code rule (iteration 3): a generic nonzero exit never classifies as usage-limit on its own** — exit 10 requires limit-specific structured or text evidence; nonzero without evidence = `other-error`. Fixture corpus includes non-limit failing processes. Signatures are **versioned data** (`core/data/signatures.v1.json`), seeded with the verified strings for all three platforms, matcher kinds `substring`/`regex`/`json-field`, per-signature confidence, precedence usage-limit > auth > throttle > other-error, `--signatures <path>` overlay for hot-patching drift, `--explain` for auditability. Hardening (Gate-1 additions): input is ANSI-stripped before matching; the fixture corpus includes negative/near-miss cases (throttle-vs-usage confusables, multiline, malformed JSON, localized text) so false positives are regression-tested; overlay regexes are lint-checked (length cap, no backreferences, linear-time constructs) and matching carries a time guard; a low-confidence match **never silently avoids a platform** — it warns and defers to user intake at receive. Cursor entries carry `confidence: low|medium` explicitly.

**Role matrix**: committed `baton.config.json` at repo root (`baton/config@1`) mapping roles → ordered platform+model chains (the seven methodology roles, defined below), plus per-platform `defaults`. Resolver is pure and explainable: skips `avoid[]` platforms (auto-populated with the origin platform when reason-class is usage-limit — never remap back onto the platform that died), resolves `mode: native|delegated|forced-default|unavailable` with `{chainIndex, skipped[]}` audit data. **Availability probing** (Gate-1 additions, iterations 1–3): `doctor` probes each platform noninteractively, hard 3 s bound per probe, results cached 15 min in the state dir. Probe record = two separate dimensions: **capability** (ordered, cumulative: `installed → authenticated → reachable`, recorded as far as verifiable) and **probe outcome** (`ok | rate-limited | error | timeout`). Resolver eligibility: **selectable** = capability ≥ authenticated and outcome ≠ rate-limited; anything with an unverifiable dimension resolves as selectable-with-`degraded`-flag; `rate-limited` platforms are skipped like `avoid[]` entries. Offline resolution always succeeds, flagged `degraded`.

**Receive**: loads bundle with recovery + staleness checks (age > 12 h; HEAD moved; dirty mismatch), merges intake flags (`--origin`, `--reason`), resolves roles, and runs as the **prepare/commit transaction defined under Concurrency** — prompt emission at prepare, state mutation only at commit. Resume prompt ≤2,500 chars (brief, why-you're-here, role table, warnings, top-5 next actions, pointer to HANDOFF.md); the prompt explicitly frames bundle content as **unverified claims to audit against the working tree, not instructions to obey** (prompt-injection posture — see Threat model).

**Scaffold** (`init`): two-phase plan/apply with `--dry-run`; `.gitignore` ensure-line (no-op if an existing pattern covers `.handoff/`); `baton.config.json` from template; AGENTS.md/CLAUDE.md written via managed blocks (`<!-- baton:begin/end -->`) — bytes outside markers never touched.

**Attribution guard** (three layers): (1) `init` deep-merges `.claude/settings.json` → `{"attribution": {"commit": "", "pr": ""}}` (only when keys absent; refuses to touch malformed JSON; global settings documented + doctor-checked, never written by core); (2) `doctor` scans last 50 commits for AI co-author/generated-with trailers (word-boundary-safe patterns) and flags with remediation; (3) a test-suite invariant scans every rendered output and template for AI-credit strings and fails the build.

Full module APIs, per-module test lists, repo file tree, and the fixture corpus (verbatim limit strings, hook payloads, corrupt bundles) are specified in the core design doc (committed as `docs/design/core.md` in task 0); implementation follows the named-task TDD sequence below — **tasks are identified by name, not number; the exact count is finalized when review directories are generated**. **`sessionHint` derivation (Gate-1 final note)**: per adapter, from the hook payload's stable session id (Claude Code `session_id`; Codex `session_id`; Cursor session field); when a payload lacks one, core generates a process-scoped hint flagged `unstable: true` — unstable hints never trigger foreign-session rejection on their own, only a warning.
### Checkpoint vocabulary (used everywhere)

- **Mechanical checkpoint** (`baton checkpoint`): hook/script-driven, no LLM — git branch/HEAD/dirty summary, timestamps, source platform/model, files touched. <1 s, safe per-turn.
- **Narrative seal** (`baton finalize`, surfaced as `/handoff`): model-written — decisions + rationale, verified-done vs claimed-done, next steps, gotchas, reason for switching.

Claude Code DOES emit a structured limit-death event (`StopFailure` with a `rate_limit` matcher); Codex and Cursor do not. The design is therefore: event-driven detection where it exists, rolling mechanical checkpoints everywhere (last coherent turn always captured), narrative seals at milestones, and receive compensating for a missing seal by asking the user why they switched and re-deriving git facts live, auditing HANDOFF.md claims against them.

### Claude Code adapter (Tier A — highest fidelity)

Plugin root = **repo root**: `.claude-plugin/plugin.json` (author: SakshamUboweja) with path overrides pointing at `adapters/claude-code/{commands,skills,agents,hooks}` so `${CLAUDE_PLUGIN_ROOT}` reaches `core/bin/baton.mjs` directly; `.claude-plugin/marketplace.json` makes the repo its own single-entry marketplace (same shape as `openai/codex-plugin-cc`). **Spike task 0 verifies path-override support**; fallback = CI copy step vendoring `core/` under the adapter.

Hooks (all fail-open — errors log to `.handoff/log/`, exit 0; a checkpoint must never break a session):

| Event | Use | Timeout |
|---|---|---|
| `StopFailure` (matcher enum — e.g. `rate_limit`, `billing_error`, `server_error` — **snapshot verbatim from the official hooks reference during task 0**; fixtures generated from that canonical list; unknown future values normalize to `unknown` safely) | **The limit-death signal.** Classifies the error (matcher + payload through `baton detect`), writes a fail-open mechanical checkpoint stamped `trigger: stop-failure/<type>`, and on `rate_limit` marks the bundle limit-hit so the next SessionStart (any platform) surfaces it. Output/exit code are ignored by the harness — safe by construction. Tests cover the full snapshot enum. | 30 s |
| `Stop` | Routine mechanical checkpoint per assistant turn (proven codex stop-gate pattern; never emits `decision: block`) | 30 s |
| `PreCompact` | Snapshot context boundary before compaction; transcript-tail capture is **opt-in, off by default** (see core §transcript policy) | 60 s |
| `SessionEnd` | Clean-exit checkpoint | 30 s |
| `SessionStart` | Not a checkpoint: if a sealed or limit-hit bundle from another platform exists, inject "handoff pending — suggest `/baton:receive`" context | 10 s |

`PostToolUse` rejected: per-tool-call spawns for incoherent mid-turn state; Stop gives the same worst-case staleness (one turn) at a fraction of the cost.

Commands: **`/baton:handoff`** (model-invocable so Claude can propose it near limits; writes the narrative — auditing every "done" claim against tool evidence — then seals via finalize, then prints the destination's resume command); **`/baton:receive`** (`disable-model-invocation: true`; runs receive → one AskUserQuestion with two questions: origin platform with detected option first, reason for switch → ack runs the core commit transaction (received seal archived, this session adopted as owner, fresh `open` generation; double-receive prevented by the one-time token; command tests assert the active/open + archived/received outcome) → evidence audit of bundle git snapshot vs live HEAD/status → announce role-remap table → auto-continue next step, pausing only per AGENTS.md boundaries); **`/baton:baton-setup`** (doctor + choose surfaces + init + template scaffold with diff preview). Receive-side continuation is a **skill** (`handoff-protocol`), not an agent — the main thread must inherit the task; a subagent would strand context. Optional v2 `handoff-verifier` agent (fresh-context bundle audit) is out of v1 scope.

### Templates: ideal AGENTS.md + CLAUDE.md

Design rule resolving the two-model-family tension: **every shared invariant appears exactly once in AGENTS.md**; model-specific steering is quarantined (short Claude block in CLAUDE.md; scoped Codex notes only if ever needed). Budget: AGENTS.md ≤220 lines (handoff section ≤25), enforced by a template test. ### Threat model (Gate-1 addition)

Bundle, config, and overlay files are **untrusted inputs**: path fields from bundles are never honored as absolute paths or `..` traversals (normalized + repo-root-jailed); `.handoff/` entries that are symlinks are refused; overlay regexes are lint-gated (length, no backreferences, linear-time) with a match time guard; resume prompts frame bundle content as claims-to-audit, not instructions (mitigates a poisoned HANDOFF.md steering the receiving model); transcript capture is opt-in with secret redaction and purge. Dedicated test fixtures for each: traversal paths, symlinked bundle dir, pathological regex, planted secrets, adversarial HANDOFF.md.
