# v1.1 hardening — plan (Milestone D)

Goal: close every deferral recorded at the Milestone B gate plus the open
dogfood finding, without changing any shipped contract (exit codes, file
layouts, token formats, and the AGENTS.md invariants are frozen). Method:
the standing TDD flow — test-author pins → verifier (cap 5 per series) →
implement → per-item commit — with Gate 2 dual review at the end of the
milestone. Everything below is falsifiable; each item names its acceptance.

## Scope (dependency-ordered)

1. **D9 — done-status persistence.** A smoke-approve resume that completes
   the final phase must persist status `done` (today the completion path
   prints done, exits 0, and leaves `running`). Accept: raw state.json
   reads `done` after the approved run completes; re-run still prints done.
2. **Trunk derivation.** Replace hardcoded `'main'` in the pipeline/worktree
   layer with the repo's actual default branch (`git symbolic-ref
   refs/remotes/origin/HEAD` → fallback `git rev-parse --abbrev-ref HEAD`
   at setup, recorded in state and reused, never re-derived mid-run).
   Accept: a master-trunk repo runs the pipeline end-to-end in tests.
3. **Per-phase child budgets.** `budgets.maxChildrenPerPhase` currently
   gates a global product; enforce it per phase/subtask. Accept: a phase
   exhausting its own budget parks naming the phase; other phases unaffected.
4. **Findings persistence.** Review findings currently live only in memory
   between iterations; persist per-gate findings history to
   `.handoff/loop/findings/<gate>.ndjson` (append-only) so a resumed run
   re-prompts with the last findings instead of an empty string. Accept:
   park → resume mid-gate carries the prior findings into the next child
   prompt; escalations embed the latest persisted findings.
5. **Streaming log caps.** superviseChild buffers child output in memory
   before the capped write; stream to the log with the cap enforced during
   capture so a runaway child cannot balloon the supervisor. Accept: a
   fixture child emitting >cap output holds supervisor memory bounded
   (observable via the capped file plus a recording-fake byte counter).
6. **Child-log redaction + purge.** Child logs under `.handoff/loop/children/`
   bypass the secret-redaction filter and the purge walk. Route the capped
   log write through the existing redaction pass and include the loop tree
   in `purge-transcript`. Accept: a planted secret in a child transcript is
   absent from the written log; the whole-tree purge test covers loop logs.
7. **Live codex marker fixture.** The `tokens used` verdict-region marker is
   pinned only against synthetic fixtures; record a real transcript
   (attempt-3 dogfood child logs are on disk) as a committed fixture and pin
   parseVerdict + tail-classification against it. Accept: the live fixture
   parses to the observed verdict.
8. **Probe integration.** `loop run`/`pipeline run` currently resolve with
   `probes: null`; feed the doctor's cached availability probes into
   resolveRoles so a rate-limited platform is skipped at spawn time (probe
   staleness > 15 min ignored, degraded flag preserved). Accept: a cached
   rate-limited probe diverts the first spawn to the fallback entry with the
   existing `degraded` audit trail; missing/stale cache resolves exactly as
   today.
9. **Pipeline smoke gate.** Optional `smoke.cmd` support for pipelines:
   after the FINAL subtask merges, run the smoke command and pause for the
   same token approval as the loop (shared implementation; same drift
   binding; `pipeline resume`/`--approve-smoke` flows reused). Accept: a
   pipeline with smoke.cmd stops awaiting approval after the last merge and
   completes only on a verified token.
10. **`--detach` (last — largest surface).** `baton loop run --detach` and
    `baton pipeline run --detach`: fork the supervisor into a background
    process group that survives the invoking terminal, write
    `.handoff/loop/supervisor.out` (capped) and print the pid + tail
    command. The run lock, reclaim, and children registry already handle
    the lifecycle; detach only changes who owns the tty. Accept: a detached
    run survives its parent's exit in an integration test (POSIX only;
    Windows documented as unsupported for v1.1).

## Out of scope

Adapters beyond what the above touches; multi-bundle `.handoff`; team
bundles; any renaming (Milestone E owns ship polish and the npm publish).

## Risks

- Trunk derivation touches merge/preflight paths proven live — pins must
  cover the master-trunk case AND re-run the main-trunk suite unchanged.
- Probe integration must never make offline resolution fail (degraded, not
  blocked) — the Gate-1-approved availability rules apply verbatim.
- Detach is platform-sensitive; keep it last so everything else lands even
  if it parks.

## Acceptance for the milestone

All ten items green with verifier-approved pins; full suite + typecheck
green; one live re-run of the pipeline dogfood (fresh clone) confirming no
regression in the proven flow; Gate 2 dual review APPROVED/WITH_NOTES with
notes folded.
