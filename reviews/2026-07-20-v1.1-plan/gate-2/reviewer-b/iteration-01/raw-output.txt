FINDINGS
================================================================================

[1][major, non-blocking] supervisor.out cap (item 10 acceptance e) is nominal,
    not actively enforced within a run.
    baton.mjs:79-93 spawnDetached accepts spec.maxBytes but NEVER references it:
    the log is opened 'w' (truncate-on-open) and the child's stdout/stderr stream
    into it unbounded for the life of the run. The comment (baton.mjs:76-78)
    concedes this — "the file itself is size-guarded on next open." So
    SUPERVISOR_OUT_CAP (loop.mjs:235, 1 MB) bounds the file only ACROSS detaches,
    not within one. The seam test (loop-run.test:840) only asserts a positive
    maxBytes is PASSED; the real-spawn test (loop-detach.test:95) only asserts
    <= 2 MB for a fast-parking child that emits almost nothing — neither exercises
    a runaway supervisor. Real-world risk is LOW (the supervisor's own stdout is
    bounded status lines; child transcripts go to separately-capped
    children/*.log), which is why this is a note, not a block. But the falsifiable
    acceptance "respects its cap" is only half-met.
    Fix (v1.2): enforce the cap in spawnDetached — e.g. stream through a size-
    counting wrapper that stops/rotates at spec.maxBytes, and add a real-spawn
    pin that emits > cap and asserts the file is truncated mid-run.

[2][minor, non-blocking] Dead production code: capLog (children.mjs:132-141) is
    exported and unit-tested but called by NO production path (superviseChild
    uses its own inline streaming cap). Harmless but misleading — a reader may
    assume the streaming path routes through it.
    Fix (v1.2): either route superviseChild's final transcript assembly through
    capLog (single source of truth for the head/marker/tail shape) or drop the
    export and its unit test.

[3][minor, non-blocking] Per-phase child budget (item 3) is in-memory only
    (loop.mjs:367 phaseChildren Map) — a crash/resume refunds the budget. The
    hard 5-iteration cap is unaffected (it lives in persisted state.iterations),
    so this does not threaten any invariant; it only means maxChildrenPerPhase is
    per-invocation rather than cumulative across resumes.
    Fix (v1.2): if a cumulative budget is intended, persist per-phase child
    counts to the journal/state; otherwise document it as per-invocation.

[4][minor, non-blocking] detachSupervisor (loop.mjs:269-272) polls up to 5 s for
    the child's lock, then prints "detached supervisor started (pid X)"
    UNCONDITIONALLY — even if the child never acquired the lock (e.g. it died at
    startup). A caller could get a success message for a run that never owns the
    lock.
    Fix (v1.2): after the poll, if the lock still does not exist, warn (and
    consider a non-zero exit) rather than reporting success.
