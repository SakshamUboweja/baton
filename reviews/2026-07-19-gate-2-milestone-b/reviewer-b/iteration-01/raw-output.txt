## FINDINGS (detail)

1. BLOCKING — claude-code children can never produce a parseable verdict in
   production. buildChildArgv's claude-code branch (children.mjs:44-51) passes
   `-p --permission-mode … --allowedTools …` with NO `--output-format json`,
   while parseVerdict('claude-code') requires structured JSON and reads the
   `result` field (children.mjs:86-95). The installed CLI's help confirms
   `--output-format` defaults to "text" (verified this session). So every real
   claude-code child returns plain text → JSON.parse fails → BLOCKED
   'unparseable' → any phase resolving to claude-code burns its full 5-cap and
   escalates, unconditionally. The plan's Child supervision contract states
   "claude-code children run with a structured output format" — the flag was
   never wired, and no test pins it (fixture runners emit JSON, masking it;
   grep for "output-format" across core/tests/adapters: zero hits).
   Fix: append `--output-format json` in the claude-code branch of
   buildChildArgv and add a unit pin asserting the flag is present for both
   reviewer and writer roles.

2. MAJOR — the resolved model is silently discarded for claude-code children:
   the claude branch of buildChildArgv never passes `--model`
   (children.mjs:44-51; codex gets `--model` at :55). Every claude-code child
   runs on the user's default model regardless of the matrix chain, which
   materially breaks "roles resolved via baton.config.json" at the spawn seam
   and makes entry-level avoidance meaningless on claude-code (avoiding a
   model the child never selects). Fix: pass `--model ${assignment.model}` and
   pin it in loop-children.test.mjs.

3. MAJOR — `baton pipeline run` has no crash/replay or concurrency story, and
   re-runs refund the 5-cap. runPipeline unconditionally builds fresh state
   (`initLoopState` at pipeline.mjs:113 — never loadLoopState), so a re-run
   after a crash or escalation resets iterations to zero: the same
   subtask-review gate gets 5 fresh iterations per invocation — a path to a
   6th+ run of a gate across invocations, against the hard invariant. No
   supervisor.lock is taken (loop.mjs has one at :141-162; pipeline has none),
   so concurrent pipeline runs race on state.json, the journal, and the seats.
   And a stale subtask branch from a previous run — explicitly on the plan's
   adversarial list — crashes unhandled at `git checkout -b`
   (pipeline.mjs:157): VERIFIED live, raw stack trace "fatal: a branch named
   'baton/wt-a/subtask-t1' already exists" (cli.mjs/bin have no catch around
   command dispatch). Fix: load-or-init state exactly as loop.mjs does; take
   the same run lock; treat an existing subtask branch as a preflight refusal
   (park) or a resume point.

4. MAJOR — pipeline discards the writer child's result and never classifies
   any child, so it has no limit failover at all. pipeline.mjs:184 awaits the
   writer spawn and ignores the returned {timedOut, exitCode, verdict}; no
   pipeline child's log is run through classify/runFailover (contrast
   loop.mjs:294-332). A writer that times out or dies on a usage limit leaves
   an empty branch that flows to review → merge as a silent no-op subtask;
   the plan positions pipeline as "loop run with the dual-worktree subtask
   cycle", inheriting the failover machinery — it doesn't. Fix: classify each
   child's transcript as loop.mjs does, route usage-limit/model-unavailable
   to runFailover, and refuse to enter review when the writer produced no
   commits on the branch.

5. MAJOR — read-only claude-code review children cannot examine what they
   review. The reviewer allowlist is exactly 'Read,Grep,Glob'
   (children.mjs:47): no scoped Bash means no `git diff`/`git log`, so a
   claude-code plan-reviewer/subtask-reviewer/final-reviewer cannot inspect a
   range at all. In pipeline, the reviewer additionally runs with cwd = the
   OTHER seat (pipeline.mjs:195) whose checkout does NOT contain the subject
   branch — the prompt says "review the diff of <branch> against main" from a
   worktree where that diff is not materialized. Verdicts would be produced
   blind (and unparseable per finding 1). Fix: grant a scoped read-only git
   allowlist (e.g. `Bash(git diff:*),Bash(git log:*),Bash(git show:*)`), and
   materialize the branch for the reviewer (fresh checkout in the reviewing
   seat is what the plan promises) or run the reviewer at the main root.

6. MAJOR — parked/escalated runs are dead ends: nothing ever emits
   LOOP_EVENT.RESUME (grep: only state.mjs:29,97 and unit tests). `loop run`
   on PARKED prints and exits 4, on ESCALATED exits 3 (loop.mjs:211-217) —
   yet ESCALATION.md instructs "Resolve the findings, then resume with baton
   loop run" (loop.mjs:244) and the stale-smoke park promises "parks for a
   fresh smoke run": both are unreachable without hand-editing
   .handoff/loop/state.json. Fix: add `baton loop resume` (or --unpark)
   emitting RESUME for parks — keeping escalation operator-only per the
   reducer's design — and make ESCALATION.md describe the real remediation.

7. MAJOR — the smoke gate binds to the literal phase id 'smoke-build'
   (loop.mjs:340). A spec with smoke.cmd set but a renamed or absent
   'smoke-build' phase silently never pauses: full-run budget spends with no
   human approval — a silent bypass of the plan's staged gate. validateLoopSpec
   never couples smoke.cmd to the phase list (spec.mjs:108-116). Fix: reject a
   spec at validation when smoke.cmd is set and no 'smoke-build' phase exists
   (or bind the gate to a declared phase attribute instead of a magic id).

8. MAJOR — supervisor run-lock acquisition is check-then-write, not atomic:
   safeReadJson at loop.mjs:142, atomicWriteJson at :162, with the full state
   load between them. Two simultaneous `loop run` invocations can both pass
   the liveness check and run concurrently — unlike the Layer-1 bundle lock's
   mkdir/EEXIST acquisition (core/src/bundle/lock.mjs:6-10) whose "same
   provably-dead machinery" the plan claims. The provably-dead takeover logic
   is faithfully mirrored; the mutual exclusion is not. Fix: acquire via
   atomic mkdir (or reuse withLock) before loading state, then stamp owner
   facts.

9. minor — plan-deferred items absent, as expected: no `--detach`/setsid
