  immediately after mergeSubtask returns ok and BEFORE the PHASE_ADVANCE

  CONJUNCTION: merge-base --is-ancestor (pipeline.mjs:267-273) AND a
  receipt for st.id (275-278). Ancestor-without-receipt parks as stale
  (280); receipt-without-ancestor falls through to the normal path and
  re-runs. Torn receipt lines are ignored (parse-null filter, 207-214) —
  fail-toward-park, the safe direction. mergeSubtask does NOT delete the

- I2: GENUINE, twice over. (a) Reclaim now matches retires to starts
  in order per childId via a queue (`inflight.get(id)?.shift()`,
  loop.mjs:185-198) — a prior tenure's retire consumes the OLDEST
  unmatched start, so a later same-id start stays in-flight and is
  killed (pinned I2a: retired 001-plan in run 1, fresh in-flight

  pinned I2b with a distinctive pgid asserted absent afterward). The

## Fresh-eyes pass — NEW findings on the fold's own code

1. MAJOR — every pipeline park is terminal, and the fold's new I1a park
   instructs a resume that does not exist. `baton pipeline` supports
   only `run` (pipeline.mjs:69); drivePipeline refuses a PARKED state
   unconditionally (pipeline.mjs:174-177); and `baton loop resume` —
   G6's fix — now refuses flavor 'pipeline' at the H5 flavor check
   (loop.mjs:269-271). So the new stale-branch park's remediation,
   "delete the branch and resume" (pipeline.mjs:280), is impossible as
   written. The only documented alternative — "archive .handoff/loop to
   start fresh" (the I3/H5 refusal wording) — makes it worse: archiving
   discards merges.ndjson, and mergeSubtask never deletes merged
   branches, so on the fresh run every previously-merged subtask branch
   is ancestor-without-receipt and immediately re-parks as "stale";
   re-init also refunds the cap counters G2 exists to protect. Net:
   pipeline's journal-based crash recovery is unreachable from ANY park
   (failover exhaustion, preflight refusal, empty branch, merge
   conflict, and now I1a) without unsupported state-file surgery. This
   is the G6 class ("parked runs are terminal"), which this gate already
   judged major and folded for the loop flavor — the I1 fold made it
   load-bearing by adding a park to the primary recovery path and
   documenting a nonexistent resume in its message. No silent loss, no
   orphans — but the milestone's recovery story dead-ends at its most
   common failure mode.
   Fix: add `baton pipeline resume` (PARKED-only RESUME transition,
   flavor-guarded, mirroring G6's loop resume — the reducer and journal
   already support it), correct the I1a park message to name it, and
   pin: park a pipeline → resume → the SAME subtask re-runs with cap
   counters intact and no re-init.

2. minor — the merged-but-receiptless crash window resumes into a
   misdiagnosing park with a mechanically-impossible instruction. A
   supervisor death between mergeSubtask returning ok and the receipt
   append (pipeline.mjs:436-440 — small window, but it exists) leaves
   ancestor-true/receipt-false, so the resume parks via I1a claiming
   "a writer likely crashed before committing" when the work IS merged
   into main; and "delete the branch" fails as written because the
   branch is still checked out in the writer's seat (mergeSubtask
   ff-syncs seats but never detaches them — git refuses to delete a
   branch checked out in a worktree). Direction is safe (loud park, no
   silent skip, no loss — the work is in main), so minor.
   Fix: hedge the park message (either a pre-commit writer crash OR a
   merge that landed without its receipt — inspect `git log
   main..<branch>` and the branch tip vs main) and include the seat
   checkout step in the remediation.
