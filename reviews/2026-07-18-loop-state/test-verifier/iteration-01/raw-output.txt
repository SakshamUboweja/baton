    20	2. **Layer 3 swap cadence**: per subtask — writer and reviewer swap seats
    21	   every subtask; the planner role plans and the merger role performs the
    22	   final adversarial merge (concrete chains live in `baton.config.json`).
    23	3. **Layer 2 smoke gate**: one staged gate after planning — the loop must
    24	   produce a minimal end-to-end slice (build + run + one real assertion) and
    25	   get explicit approval before the full run; the 5-iteration cap governs
    26	   every gate.
    27	4. **Driver**: a supervisor CLI — spawns headless role children
    28	   (`claude -p` / `codex exec`), parses verdicts, and invokes baton handoff

    33	### Loop spec
    34	
    35	`loop.json` at repo root (schema `baton/loop@1`), scaffolded by
    36	`baton loop init "<goal>"`:
    37	
    38	- `goal`, `constraints[]` (falsifiable acceptance criteria — the loop's exit
    39	  condition), `smoke` ({cmd, expect} — the staged-gate slice definition),
    40	- `phases` — an ordered list of `{id, role}` entries: `id` is a free label
    41	  for progress display; `role` MUST be a matrix role ID (validation fails on
    42	  any unknown role before a child spawns). Default:
    43	  plan(`planner`) → gate-1(`plan-reviewer`) → smoke — itself a TDD mini-cycle
    44	  per the repo contract: smoke-tests(`test-author`) →
    45	  smoke-verify(`test-verifier`) → smoke-build(`implementer`) → the human
    46	  smoke gate — → per-subtask cycle (`test-author` → `test-verifier` →
    47	  `implementer` → `subtask-reviewer`) → gate-2(`final-reviewer-a`,
    48	  `final-reviewer-b`) → done,
    49	- `budgets` ({iterationCap: 5, perRoleTimeoutMin, maxChildrenPerPhase}),
    50	- roles resolve through the existing `baton.config.json` matrix — never
    51	  hardcoded models.

    53	### Role-matrix additions (Gate-1 iteration 1, finding 1)
    54	
    55	The loop references roles by ID only; every referenced role must exist in the
    56	matrix or `loop.json` validation fails (`unknown role '<id>'`, exit 2, before
    57	any child spawns). Four roles are ADDED to `baton.config.json` +
    58	`templates/baton.config.json.tpl` in the first implementation task:
    59	
    60	- `subtask-reviewer` — per-subtask diff review inside the loop cycle.
    61	- `merger` — the only role that writes main in pipeline mode; adversarial
    62	  re-check before merge.
    63	- `worker-a`, `worker-b` — the two pipeline seats. Subtask N assigns
    64	  writer = seat (N mod 2), reviewer = the other seat; the SEATS swap, and each
    65	  seat's concrete platform/model comes from its configured chain via the
    66	  resolver. No vendor or model name appears in this plan, child prompts, or
    67	  loop code — chains live in config only.

    69	### `baton loop` (Layer 2)
    70	
    71	- `baton loop init <goal>` — scaffold spec + plan template; idempotent,
    72	  dry-run-able, same two-phase plan/apply discipline as `baton init`.
    73	- `baton loop run [--approve-smoke <token>]` — the state machine. State lives
    74	  in gitignored `.handoff/loop/state.json` + `journal.ndjson` (same atomic
    75	  write + journal replay machinery as the bundle; loop position is also
    76	  checkpointed into the handoff bundle so a limit death carries it).
    77	
    78	### Root + ownership discipline (Gate-1 iteration 1, finding 2)
    79	
    80	One authoritative root: the MAIN repo root where `loop.json` lives. The
    81	supervisor is the SOLE writer of `.handoff/loop/` and of the main root's
    82	handoff bundle; every supervisor-driven baton invocation passes explicit
    83	`--root <mainRoot>` and a supervisor-owned stable session hint
    84	(`--session loop-<runId>` — a NEW flag added to `checkpoint`; `receive`
    85	already has it), so the bundle has exactly one stable owner.
    86	
    87	**Child-hook policy (Gate-1 iteration 2, finding 1; iteration 3,
    88	finding 1)** — children never touch OR read any bundle, by construction: the
    89	supervisor sets `BATON_SUPERVISED_CHILD=1` in every child's environment, and
    90	EVERY baton hook command — the hook entrypoints, `baton checkpoint`, and
    91	`baton session-start` (which would otherwise read the bundle and inject
    92	pending-handoff resume context into the child) — quietly no-ops (exit 0,
    93	empty output) when it is set. This covers
    94	Layer-2 children running in the MAIN root (where root discovery would
    95	otherwise find the supervisor-owned bundle and the foreign-session guard
    96	would reject their stable hints) and pipeline children in worktrees alike;
    97	narrative checkpointing for supervised work is the supervisor's job, driven
    98	by parsed child results. Contract tests: (a) Layer-2 — two concurrent
    99	main-root children with distinct stable session hints and live hooks →
   100	zero bundle mutations, zero foreign-session rejections, supervisor
   101	`--session` checkpoints land; (b) pipeline — same from two worktrees while
   102	the supervisor writes loop state.
   103	- Each role invocation is a headless child under the supervisor:
   104	  - claude-code roles: `claude -p "<role prompt>" --permission-mode
   105	    acceptEdits --allowedTools ...` (allowlist per role: reviewers read-only).
   106	  - codex roles: `codex exec -C <root> -s <sandbox> --model <m> -c
   107	    model_reasoning_effort=<e> "<prompt>" </dev/null` (stdin closed — the
   108	    stdin-hang class is a known field failure).
   109	  - Verdict contract: children end with the structured tail
   110	    (`VERDICT: APPROVED|APPROVED_WITH_NOTES|BLOCKED` + FINDINGS) already used
   111	    by every review gate; the supervisor parses exactly that.
   112	
   113	### Child supervision contract (Gate-1 iteration 1, finding 7)
   114	
   115	`children.mjs` owns the full child lifecycle, not just argv assembly:
   116	
   117	- Spawn detached in its OWN process group; stdin closed at spawn (the
   118	  codex-exec stdin-hang class); per-role timeout → SIGTERM to the group, 10 s
   119	  grace, then SIGKILL to the group (no zombie grandchildren; reap verified in
   120	  tests with a child that forks a sleeper).
   121	- Full child output streams to `.handoff/loop/children/<child-id>.log` with a
   122	  byte cap (head preserved, middle truncated with a marker — the verdict tail
   123	  is at the END so the tail is never truncated).
   124	- **Verdict parsing is region-bounded (prompt-echo defense)**: only the
   125	  child's FINAL message region is parsed — claude-code children run with a
   126	  structured output format and the parser reads the result field; codex
   127	  children are parsed strictly AFTER the last `tokens used` marker. The
   128	  prompt region (which quotes `VERDICT:` in its instructions) is never
   129	  scanned. Multiple tails in the final region → the LAST one wins.
   130	- An unparseable, absent, or truncated verdict is BLOCKED-with-escalation,
   131	  never APPROVED; a child that exits after making edits but before a verdict
   132	  parks the subtask with its worktree preserved for inspection.
   133	- A generic nonzero exit classifies as `other-error` (existing classifier
   134	  rule) → the loop retries once, then parks; it NEVER triggers limit failover
   135	  without limit-specific evidence.
   136	- Fixture-driven tests: prompt echo, multiple verdict tails, truncated
   137	  transcript, timeout kill/reap, zombie grandchild, non-limit nonzero exit.
   138	
   139	### Supervisor lifetime and recovery (Gate-1 iteration 2, finding 5)
   140	
   141	"Survives the operator's session ending" is a defined mechanism, not a hope:
   142	
   143	- `baton loop run` is FOREGROUND by default. `--detach` re-launches the
   144	  supervisor in its own session (`setsid`), output to
   145	  `.handoff/loop/supervisor.log`, and returns.
   146	- A run lock `.handoff/loop/supervisor.lock` carries {pid, process
   147	  start-time, host, runId} — the same provably-dead machinery as the
   148	  Layer-1 bundle lock. A second `loop run` against a LIVE supervisor is
   149	  refused; against a provably-dead one it recovers.
   150	- The state machine is journal-replayable: recovery replays
   151	  `journal.ndjson`, marks any in-flight child of the dead supervisor as
   152	  interrupted (its process group is gone or killed on adoption), and either
   153	  continues from the last completed step or parks with an escalation note —
   154	  never re-runs a completed gate iteration.
   155	- Acceptance adds a supervisor-death test: kill the supervisor (and its
   156	  launching session) mid-subtask → a fresh `loop run` recovers via the
   157	  journal and continues or parks; no orphaned children survive (process
   158	  groups reaped on adoption).
   159	
   160	- **Smoke gate (staleness-proof — Gate-1 iteration 1, finding 8; TDD order —
   161	  iteration 2, finding 2)**: after gate-1, the smoke slice is built as a TDD
   162	  mini-cycle (test-author writes the failing smoke assertion → test-verifier
   163	  approves it → implementer writes only enough to pass it — the repo TDD
   164	  contract applies to the slice, not just to subtasks); the supervisor then
   165	  runs `smoke.cmd`, records output, and STOPS, writing
   166	  `.handoff/loop/SMOKE-REVIEW.md` plus `smoke-approval.json` containing an
   167	  approval token = digest over {loop-state digest, smoke.cmd, output digest,
   168	  HEAD, content-sensitive git digest (existing snapshot machinery), child
   169	  assignment}. Resuming requires `baton loop run --approve-smoke <token>`;
   170	  the supervisor recomputes the digest first and REFUSES a drifted token
   171	  (anything changed since the human looked) — it parks for a fresh smoke run
   172	  instead. No full-run budget is spent before a valid approval.
   173	- **Limit failover (the baton integration — Gate-1 iteration 1, finding 3)**:
   174	  an exact transaction, not a loose chain. On child death: (1) reap the
   175	  process group and freeze the transcript; (2) classify via `baton detect`;
   176	  non-limit → the retry/park path above. On a limit classification:
   177	  (3) checkpoint the loop position INTO THE BUNDLE (supervisor
   178	  `checkpoint --session loop-<runId>`) so the seal carries it and the receipt
   179	  token binds it; (4) seal via `finalize --reason-class usage-limit --root
   180	  <mainRoot>` (an already-dead/unsealed bundle takes the degraded-open path
   181	  receive already supports); (5) refresh probes; (6) `receive --prepare` then
   182	  `--commit` back-to-back with IDENTICAL intake flags, the supervisor session
   183	  hint, and the same explicit root, with NO intervening writes; (7) resolver
   184	  output (with the dead entry avoided) picks the relaunch platform+model;
   185	  (8) relaunch the child with the resume prompt. A stale-token rejection
   186	  triggers ONE automatic re-prepare/commit retry; a second failure parks.
   187	  Between prepare and commit the failover holds the loop transaction lock and
   188	  writes NOTHING — `.handoff/loop/` writes are not token-bound inputs, so
   189	  this is enforced by construction and ASSERTED in tests (fs spy: zero
   190	  `.handoff/loop/` writes inside the window), not assumed. Drift-rejection
   191	  tests inject the inputs the token actually binds: git change and probe
   192	  refresh between prepare and commit → stale-token → one retry path. Plus:
   193	  open-bundle (unsealed) limit death; the full seal→receive→relaunch happy
   194	  path.
   195	- **Model-level failover (Gate-1 iteration 1, finding 4)**: the resolver
   196	  gains entry-level avoidance — `avoidEntries: [{platform, model}]` alongside
   197	  the existing platform-level `avoid[]` — and the classifier gains a
   198	  `model-unavailable` signature class (distinct from usage-limit; seeded with
   199	  the verified account-tier rejection string). A model rejected at spawn adds
   200	  its {platform, model} entry to avoidEntries and re-resolves: other models
   201	  on the SAME platform remain selectable. Named test: first chain entry
   202	  rejected as model-unavailable → the next entry on the same platform is
   203	  selected, with no platform-wide avoidance.
   204	  All platforms/entries exhausted → the loop parks with a resume-at hint
   205	  instead of dying.
   206	- **Caps**: every gate loops at most 5 iterations; on exhaustion the loop
   207	  parks and escalates (writes `.handoff/loop/ESCALATION.md`, notifies) — never
   208	  a 6th run.
   209	
   210	### `baton pipeline` (Layer 3 — a loop preset)
   211	
   212	- `baton pipeline run` = `loop run` with the dual-worktree subtask cycle:
   213	  - Two persistent worktrees `.worktrees/wt-a`, `.worktrees/wt-b`
   214	    (`git worktree add`); `pipeline init` ensure-lines `.worktrees/` into
   215	    `.gitignore` (same idempotent machinery as the `.handoff/` line).
   216	  - Subtask N: the writer seat implements on a namespaced branch
   217	    (`baton/wt-<seat>/subtask-N`) in its worktree; the reviewer seat reviews
   218	    the diff from the OTHER worktree (fresh checkout, fresh context). Seats
   219	    swap every subtask: worker-a writes / worker-b reviews → worker-b writes /
   220	    worker-a reviews → … (concrete models per seat come from the role
   221	    matrix — see Role-matrix additions).
   222	  - Verdict flow: APPROVED → the merger role adversarially re-checks and
   223	    merges into main (the ONLY writer to main); BLOCKED → writer fixes,
   224	    ≤5 iterations, then escalate. After each merge both worktrees
   225	    fast-forward.
   226	
   227	  **Worktree transaction layer (Gate-1 iteration 1, finding 5)** —
   228	  `worktrees.mjs` treats every git operation as a guarded transaction:
   229	  - Branch namespace `baton/wt-*/…` is loop-owned; anything else is never
   230	    touched.
   231	  - Preflight before each child: worktree exists in `git worktree list`,
   232	    index clean, HEAD on the expected branch — a dirty or drifted worktree
   233	    parks the subtask instead of spawning.
   234	  - Postflight after each child: HEAD still on the expected branch, main
   235	    unmoved by the child — violation parks with the evidence.
   236	  - Merges run under a supervisor-held merge lock; worktree sync after merge
   237	    is ff-only (a non-ff sync is a corruption signal → park); merge conflicts
   238	    park + escalate, never auto-resolved.
   239	  - Stale metadata self-heals: a raw-deleted worktree directory is detected
   240	    (`git worktree list` vs fs), pruned (`git worktree prune`), and re-added;
   241	    teardown uses `git worktree remove` + branch deletion so acceptance
   242	    constraint 5 (no residue) holds.
   243	  - Adversarial tests: stale branch from a previous run, dirty worker,
   244	    main moved mid-subtask, merge conflict, raw-deleted `.worktrees/`,
   245	    untracked `.worktrees/` (missing gitignore line → doctor check).
   246	
   247	  **Attribution enforcement for child commits (Gate-1 iteration 1,
   248	  finding 6)** — the invariant is enforced, not assumed:
   249	  - The supervisor sets `GIT_AUTHOR_NAME/EMAIL` and `GIT_COMMITTER_NAME/EMAIL`
   250	    (sole author identity) in EVERY child's environment.
   251	  - Every merge is gated on an attribution scan over the exact range
   252	    `main..baton/wt-<seat>/subtask-N` — author/committer identity plus the
   253	    forbidden-trailer patterns (the existing doctor patterns, applied to the
   254	    full range, not a last-50 window). A violation blocks the merge and
   255	    parks.
   256	  - The existing doctor 50-commit scan remains the repo-wide backstop.

   273	### Acceptance constraints (the loop's exit condition)
   274	
   275	1. On a fixture repo, `baton loop run` drives a toy goal end-to-end headlessly:
   276	   plan → gate-1 → smoke slice AS A TDD MINI-CYCLE (failing smoke assertion
   277	   authored and verifier-approved BEFORE the slice implementation — order
   278	   asserted from the journal) → parked for approval → (approved) → 2 subtasks
   279	   TDD → gate-2 → done, with review artifacts under `reviews/` in the fixture.
   280	   Layer-2 children run in the main root with live hooks and neither mutate
   281	   NOR read the supervisor-owned bundle: under `BATON_SUPERVISED_CHILD=1`,
   282	   hook commands on all three platforms produce zero bundle writes AND zero
   283	   session-start resume context (both asserted).
   284	2. Simulated limit death (child exits with a verbatim limit banner) mid-subtask
   285	   → the loop seals, remaps the role off the dead platform, resumes on the
   286	   other harness, and completes the subtask. Chained A→B→A tested. Separately:
   287	   a model-unavailable rejection at spawn selects the NEXT entry on the same
   288	   platform (no platform-wide avoidance).
   289	3. `baton pipeline run` completes 2 subtasks with alternating writer/reviewer
   290	   across the two worktrees; the attribution range scan passes for main AND
   291	   both worker branch ranges (child commits included) — sole author, zero AI
   292	   attribution; reviewer children run read-only.
   293	4. The 5-cap parks + escalates on every gate (unit-forced exhaustion test);
   294	   no gate ever runs a 6th iteration. Killing the supervisor (and its
   295	   launching session) mid-subtask → a fresh `loop run` recovers via the
   296	   journal and continues or parks, with no orphaned children.
   297	5. Deleting `.handoff/` and `.worktrees/` leaves the fixture repo exactly as
   298	   a plain git repo (no residue outside gitignored trees).
   299	6. All existing 878 tests stay green; the new suite covers spec validation,
   300	   state-machine transitions (unit, injected io), child verdict parsing
   301	   (fixture transcripts), failover (fake children), and worktree discipline.
   302	
   303	### Top risks
   304	
   305	1. **Headless permission surfaces** — Claude Code children need permission
   306	   flags that stay inside the sandboxed repo; reviewers get read-only
   307	   allowlists. Mitigation: per-role allowlist table + spike task 0.
   308	2. **Verdict-parse drift** — models sometimes wrap the tail; the
   309	   region-bounded parser (Child supervision contract) takes the LAST tail in
   310	   the final-message region only and treats an unparseable one as
   311	   BLOCKED-with-escalation, never as APPROVED.
   312	3. **Cost runaway** — per-phase child caps + iteration caps + the smoke gate
   313	   before any full-run spend; every child's token/duration logged to the loop
   314	   journal.
   315	4. **Worktree state divergence** — only the merger writes main; workers are
   316	   branch-jailed; ff-sync after each merge; `baton pipeline doctor` checks
   317	   worktree health.
   318	5. **Cross-platform child API drift** — the spawn contract lives in ONE module
   319	   (children.mjs) with per-platform fixtures, same seam discipline as
   320	   normalize.mjs.

    40	export function makeMemfs(initialFiles = {}) {
    41	  const store = new Map(); // path -> string content
    42	  const dirs = new Set(['/']);
    43	  const mtimes = new Map();
    44	  const history = [];
    45	  let clock = 0;
    46	
    47	  const snapshot = () => Object.fromEntries(store);
    48	  const record = (op, paths) => history.push({ op, paths, files: snapshot() });
    49	  const touch = (np) => mtimes.set(np, ++clock);
    50	
    51	  const mkdirp = (np) => {
    52	    let cur = '';
    53	    for (const part of np.split('/').filter(Boolean)) {
    54	      cur = cur + '/' + part;
    55	      dirs.add(cur);
    56	    }
    57	  };
    58	
    59	  const ensureParent = (np, syscall) => {
    60	    const parent = dirname(np);
    61	    if (parent === '/' ) return;
    62	    if (!dirs.has(parent)) throw fsError('ENOENT', syscall, np);
    63	  };
    64	
    65	  for (const [p, content] of Object.entries(initialFiles)) {
    66	    const np = normalize(p);
    67	    mkdirp(dirname(np));
    68	    store.set(np, String(content));
    69	    touch(np);
    70	  }
    71	
    72	  const fs = {
    73	    readFileSync(p /*, enc */) {
    74	      const np = normalize(p);
    75	      if (!store.has(np)) throw fsError('ENOENT', 'open', np);
    76	      return store.get(np);
    77	    },
    78	
    79	    writeFileSync(p, data /*, enc */) {
    80	      const np = normalize(p);
    81	      ensureParent(np, 'open');
    82	      store.set(np, String(data));
    83	      touch(np);
    84	      record('writeFileSync', [np]);
    85	    },
    86	
    87	    appendFileSync(p, data) {
    88	      const np = normalize(p);
    89	      ensureParent(np, 'open');
    90	      store.set(np, (store.get(np) || '') + String(data));
    91	      touch(np);
    92	      record('appendFileSync', [np]);
    93	    },
    94	
    95	    renameSync(from, to) {
    96	      const nf = normalize(from);
    97	      const nt = normalize(to);
    98	      if (store.has(nf)) {
    99	        ensureParent(nt, 'rename');
   100	        const content = store.get(nf);
   101	        store.delete(nf);
   102	        store.set(nt, content);
   103	        touch(nt);
   104	        record('renameSync', [nf, nt]);
   105	        return;
   106	      }
   107	      // Directory rename (atomic move of the node and all descendants) — the
   108	      // lock's dead-reclaim arbitration renames the stale lock dir aside.
   109	      if (dirs.has(nf)) {
   110	        ensureParent(nt, 'rename');
   111	        const pre = nf + '/';
   112	        dirs.delete(nf);
   113	        dirs.add(nt);
   114	        for (const k of [...store.keys()]) {
   115	          if (k.startsWith(pre)) {
   116	            store.set(nt + k.slice(nf.length), store.get(k));
   117	            store.delete(k);
   118	          }
   119	        }
   120	        for (const d of [...dirs]) {
   121	          if (d !== nt && d.startsWith(pre)) {
   122	            dirs.add(nt + d.slice(nf.length));
   123	            dirs.delete(d);
   124	          }
   125	        }
   126	        touch(nt);
   127	        record('renameSync', [nf, nt]);
   128	        return;
   129	      }
   130	      throw fsError('ENOENT', 'rename', nf);
   131	    },
   132	
   133	    mkdirSync(p, opts = {}) {
   134	      const np = normalize(p);
   135	      if (opts.recursive) {
   136	        mkdirp(np);
   137	        record('mkdirSync', [np]);
   138	        return undefined;
   139	      }
   140	      ensureParent(np, 'mkdir');
   141	      if (dirs.has(np) || store.has(np)) throw fsError('EEXIST', 'mkdir', np);
   142	      dirs.add(np);
   143	      record('mkdirSync', [np]);
   144	      return undefined;
   145	    },
   146	
   147	    existsSync(p) {
   148	      const np = normalize(p);
   149	      return store.has(np) || dirs.has(np);
   150	    },
   151	
   152	    readdirSync(p) {
   153	      const np = normalize(p);
   154	      if (!dirs.has(np)) {
   155	        if (store.has(np)) throw fsError('ENOTDIR', 'scandir', np);
   156	        throw fsError('ENOENT', 'scandir', np);
   157	      }
   158	      const names = new Set();
   159	      const collect = (k) => {
   160	        if (k !== np && dirname(k) === np) names.add(basename(k, np));
   161	      };
   162	      for (const k of store.keys()) collect(k);
   163	      for (const d of dirs) collect(d);
   164	      return [...names];
   165	    },
   166	
   167	    unlinkSync(p) {
   168	      const np = normalize(p);
   169	      if (!store.has(np)) throw fsError('ENOENT', 'unlink', np);
   170	      store.delete(np);
   171	      record('unlinkSync', [np]);
   172	    },
   173	
   174	    rmSync(p, opts = {}) {
   175	      const np = normalize(p);
   176	      const isFile = store.has(np);
   177	      const isDir = dirs.has(np);
   178	      if (!isFile && !isDir) {
   179	        if (opts.force) return;
   180	        throw fsError('ENOENT', 'rm', np);
   181	      }
   182	      if (isFile) store.delete(np);
   183	      if (isDir) {
   184	        const pre = np + '/';
   185	        if (!opts.recursive) {
   186	          const hasChildren = [...store.keys(), ...dirs].some((k) => k !== np && k.startsWith(pre));
   187	          if (hasChildren) throw fsError('ENOTEMPTY', 'rmdir', np);
   188	          dirs.delete(np);
   189	        } else {
   190	          for (const k of [...store.keys()]) if (k === np || k.startsWith(pre)) store.delete(k);
   191	          for (const d of [...dirs]) if (d === np || d.startsWith(pre)) dirs.delete(d);
   192	        }
   193	      }
   194	      record('rmSync', [np]);
   195	    },
   196	
   197	    statSync(p) {
   198	      const np = normalize(p);
   199	      if (store.has(np)) {
   200	        const size = Buffer.byteLength(store.get(np));
   201	        return { isFile: () => true, isDirectory: () => false, isSymbolicLink: () => false, size, mtimeMs: mtimes.get(np) || 0 };
   202	      }
   203	      if (dirs.has(np)) {
   204	        return { isFile: () => false, isDirectory: () => true, isSymbolicLink: () => false, size: 0, mtimeMs: mtimes.get(np) || 0 };
   205	      }
   206	      throw fsError('ENOENT', 'stat', np);
   207	    },
   208	
   209	    // The fake cannot represent symlinks, so lstat === stat and realpath is
   210	    // normalization. Symlink-refusal behavior is proven over the real fs in
   211	    // tests/integration/symlink-escape.test.mjs.
   212	    lstatSync(p) {
   213	      return fs.statSync(p);
   214	    },
   215	
   216	    realpathSync(p) {
   217	      const np = normalize(p);
   218	      if (!store.has(np) && !dirs.has(np)) throw fsError('ENOENT', 'realpath', np);
   219	      return np;
   220	    },
   221	
   222	    copyFileSync(src, dest) {
   223	      const ns = normalize(src);
   224	      const nd = normalize(dest);
   225	      if (!store.has(ns)) throw fsError('ENOENT', 'copyfile', ns);
   226	      ensureParent(nd, 'copyfile');
   227	      store.set(nd, store.get(ns));
   228	      touch(nd);
   229	      record('copyFileSync', [ns, nd]);
   230	    },
   231	  };
   232	
   233	  // Introspection hook for atomicity assertions; not part of the real fs API.
   234	  fs.__history = history;
   235	
   236	  return { fs, files: () => snapshot() };
   237	}
